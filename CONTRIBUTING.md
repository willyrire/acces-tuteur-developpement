# Contribuer à Accès Tuteur

Merci de votre intérêt envers le développement d’**Accès Tuteur**.

Bien que le code source principal de la plateforme demeure privé, ce dépôt permet aux utilisateurs, aux développeurs et aux autres personnes intéressées de participer à son amélioration par l’intermédiaire de signalements, de suggestions et de discussions techniques.

## Types de contributions

Les contributions peuvent notamment prendre les formes suivantes :

- signalement de bogues ou de comportements inattendus;
- proposition de nouvelles fonctionnalités;
- suggestion d’améliorations de l’expérience utilisateur;
- correction ou amélioration de la documentation publique;
- proposition de solutions techniques;
- commentaires constructifs sur les orientations du projet.

Toute contribution doit être pertinente, respectueuse et suffisamment documentée pour permettre son évaluation.

## Signaler un bogue

Avant de soumettre un signalement, veuillez vérifier si une issue similaire existe déjà.

Un signalement devrait idéalement contenir :

1. **Un titre descriptif :** résumer clairement le problème.
2. **Une description :** expliquer le comportement observé.
3. **Les étapes de reproduction :** indiquer comment reproduire le problème.
4. **Le comportement attendu :** préciser le résultat normalement souhaité.
5. **L’environnement :** navigateur, appareil ou système d’exploitation, lorsque pertinent.
6. **Des éléments complémentaires :** captures d’écran ou messages d’erreur, si nécessaire.

Veuillez retirer toute donnée personnelle ou confidentielle des éléments partagés.

## Proposer une fonctionnalité

Les propositions de nouvelles fonctionnalités sont les bienvenues.

Une demande devrait idéalement expliquer :

- le problème ou le besoin identifié;
- la solution proposée;
- les avantages attendus pour les utilisateurs;
- les comportements particuliers à considérer;
- toute autre information permettant d’évaluer la pertinence de la proposition.

Les propositions sont évaluées en fonction des objectifs du projet, des ressources disponibles, de leur faisabilité et de leur impact potentiel.

## Classification des issues

Les issues peuvent être organisées selon trois catégories principales de labels.

| Catégorie | Préfixe | Description |
|---|---|---|
| Système | `system:` | Module ou composant concerné. |
| Type | `type:` | Nature du signalement ou de la tâche. |
| Priorité | `priority:` | Niveau de priorité attribué. |

La classification et la priorisation sont effectuées par les responsables du dépôt.

Les labels peuvent être ajoutés, modifiés ou retirés selon l’évolution des besoins.

## Contributions au code

Le code source principal d’Accès Tuteur n’est pas publié dans ce dépôt.

Par conséquent, les contributions directes aux composants privés de l’application ne sont pas prises en charge par l’intermédiaire de ce dépôt.

Les propositions de modifications à la documentation publique peuvent néanmoins être soumises pour évaluation.

**Une pull request ne garantit pas l’intégration des modifications proposées.**

## Règles de participation

Toute personne participant au dépôt est invitée à :

- maintenir des échanges respectueux et constructifs;
- éviter les attaques personnelles et les propos discriminatoires;
- fournir des informations exactes dans la mesure du possible;
- respecter la confidentialité des utilisateurs;
- éviter les publications répétitives ou sans rapport avec le projet;
- respecter la propriété intellectuelle des tiers.
